## Why archmax harness

Reliable automation with AI agents should follow the process, and the people who
own that process should be able to author it. Today that is out of reach for most
domain experts. Current automation tools fall short in three ways.

- **The agent is a step, not the process.** The agent sits inside a fixed graph,
  so its flexibility ends at the edge of one node. The process stays as rigid as
  the diagram someone drew.
- **The process and its implementation drift apart.** Every business process is
  restated as a technical graph. That makes two artifacts with two owners, and
  keeping them in step never stops costing effort.
- **Complex data still ends up in code.** Nested payloads, loops and arithmetic
  land in a code node. The person who owns the process cannot read it, let alone
  change it.

The archmax harness turns this around. The agent runs the whole process, and one
`workflow.yaml` both describes it and enforces it. Data work happens in a
sandbox the same rules govern.

## The agent sees one state at a time

The archmax harness renders the state in force: its tool surface, its outgoing edges, its
hooks. The runtime reads the rest from the spec file.

Two things follow. An injected instruction has one state and its edges to work
with, because that is all the prompt holds. And the cached prompt stays the same
size whether the workflow has six states or sixty.

## What the archmax harness is

The archmax harness is a runtime library for Node and TypeScript (ESM). It is a thin layer over
[LangChain Deep Agents](https://docs.langchain.com/oss/javascript/deepagents/overview).
It wires up a model, serves the agent's workspace through a Deep Agents backend,
loads skills, and enforces `workflow.yaml`.

Everything specific to your agent lives in the workspace as files: the spec, skill
bundles, hook scripts, and data. The runtime stays generic, so the same library can
run a support triage agent and a nightly reporting job. The workspace can live on
any Deep Agents backend: a local directory, an object store, a remote service.
